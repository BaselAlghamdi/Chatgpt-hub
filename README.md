# Basel M. Alghamdi | Finance Portfolio

موقع كامل بـNext.js للنشر على Vercel، مع لوحة إدارة للمحتوى وقاعدة بيانات وتخزين ملفات على Supabase. التصميم التحريري بالأخضر محفوظ، ولا توجد تقارير أو مشاريع تجريبية.

## النشر على Vercel

1. أنشئ مشروع Supabase خاصًا بهذا الموقع. من **SQL Editor** نفّذ ملف [`supabase/schema.sql`](supabase/schema.sql) كاملًا. ينشئ الجداول وحاوية ملفات خاصة، دون أي محتوى تجريبي.
2. من **Authentication → Users → Add user** أنشئ حسابك ببريدك وكلمة مرور تختارها، مع تأكيد البريد. انسخ **User ID**. من إعدادات Auth عطّل تسجيل مستخدمين جدد إذا لم تحتج إليه. الموقع نفسه لا يتضمن تسجيلًا للزوار.
3. في **Vercel → Add New → Project** استورد مستودعك المستقل **`BaselAlghamdi/Chatgpt-hub`** بعد رفع ملفات هذه الحزمة إليه. اختر **Next.js**، والمجلد الجذري **`./`**، واترك Output Directory تلقائيًا.
4. أضف القيم التالية في **Environment Variables**. استخدم بيانات مشروع Supabase الخاص بك، وليس الكلمات التوضيحية في `.env.example`:

| المتغير | القيمة المطلوبة |
| --- | --- |
| `SUPABASE_URL` | Project URL من Supabase |
| `SUPABASE_ANON_KEY` | المفتاح العام `anon` أو publishable key |
| `SUPABASE_SERVICE_ROLE_KEY` | مفتاح `service_role` السري، من إعدادات API Keys |
| `ADMIN_USER_ID` | UUID لحسابك من Authentication → Users |
| `ADMIN_EMAIL` | بريد حساب الإدارة نفسه |
| `SITE_URL` | رابط الموقع الكامل، مثل `https://your-domain.com` |

5. تأكد من **Settings → Git → Production Branch = `main`** ثم Deploy.
6. افتح **`https://رابط-موقعك/desk-65efdcc4b137b000`** وسجّل الدخول بالحساب الذي أنشأته. لا يوجد حساب أو كلمة مرور افتراضية في الكود.
7. في **Vercel → Settings → Domains** أضف الدومين، وطبّق سجلات DNS التي يعرضها Vercel لدى مزود الدومين. حدّث `SITE_URL` إلى الدومين النهائي وأعد النشر. لا تحتاج إلى تغيير الكود لربط الدومين.

**التثبيت الأول:** الصفحات العامة تعمل بمعلوماتك الأساسية إذا لم تضبط Supabase بعد؛ الإدارة تبقى مغلقة حتى تكتمل الإعدادات. عند ربط قاعدة بيانات فارغة تكون التقارير والمشاريع والشهادات فارغة فعلًا. لا يوجد زر نشر صوري أو حفظ محلي بديل.

## استخدام الإدارة

- **Research:** عنوان، رابط، ملخص، محتوى Markdown، تصنيفات، وسوم، غلاف، صور داخل المقال، مرفقات، مسودة أو منشور.
- **Projects:** شرح المشروع، صور، ملفات PDF/Excel/PowerPoint وروابط تحميل خارجية.
- **Certifications:** اسم الشهادة، الجهة، الصورة ووصفها، التاريخ، رابط التحقق من الاعتماد.
- **Academic honors:** شهادات التفوق والتكريم الجامعي. تظهر داخل قسم التعليم في About.
- **About & contact:** الاسم، التعريف، النبذة، الجامعة، التخصص، المعدل، الاهتمامات، البريد وLinkedIn.
- عناوين Markdown من المستوى الثاني والثالث (`##` و`###`) تبني فهرس **In this article** تلقائيًا. يدعم المحرر المعاينة، الجداول، الروابط والاقتباسات.
- الحفظ صريح. ارفع الملف ثم احفظ المدخل؛ اختيار Published ثم الحفظ يجعله عامًا. الرجوع إلى Draft يسحب الصفحة وملفاتها من الوصول العام، ما لم يكن الملف مستخدمًا أيضًا في مدخل منشور آخر.
- رفع الملف الواحد حتى **4 MB** بما يتوافق مع طلبات Vercel. الملفات الأكبر يمكن إضافتها كرابط HTTPS خارجي. الصور: JPG/PNG/WebP/GIF. المستندات: PDF/XLSX/PPTX. حوّل XLS القديم إلى XLSX.
- روابط الملفات الخارجية تخضع لصلاحيات مزودها. الملفات المحلية تبقى في حاوية خاصة وتُعرض فقط بعد التحقق من صلاحيات المدخل.
- جلسة الإدارة حتى ساعة. إذا انتهت، افتح `/desk-65efdcc4b137b000` في نافذة أخرى وسجّل الدخول مجددًا، ثم أعد الحفظ من نافذة المحرر؛ التغييرات تبقى فيها. لا توجد كلمة مرور أو رمز دخول مخزن في localStorage.
- **Export content** ينزّل نسخة JSON من النصوص والإعدادات وبيانات المرفقات. لا يحتوي JSON على بايتات الصور والملفات؛ انسخ محتويات `portfolio-files` أيضًا من Supabase عند أخذ نسخة احتياطية أو النقل إلى مشروع آخر. تصدير الكود إلى GitHub لا ينقل محتوى قاعدة البيانات تلقائيًا.
- تنزيل المقال ينتج نسخة HTML قابلة للقراءة والطباعة. صورها تتطلب الاتصال بالموقع؛ للطباعة إلى PDF استخدم Print article.

## التشغيل المحلي

يتطلب Node.js 22.15 أو أحدث، ويفضل Node.js 24 LTS.

```bash
npm ci
cp .env.example .env.local
# أدخل قيم Supabase في .env.local
npm run dev
```

يفتح محليًا على المنفذ 4173. فحص الإنتاج:

```bash
npm test
npm run typecheck
npm run build
npm start
```

## البنية والحماية

- `app/`: الصفحات وواجهات API، بما فيها `/desk-65efdcc4b137b000`.
- `components/`: الواجهة والمحرر وعناصر الوصول المهيأة.
- `lib/server/`: الوصول إلى البيانات والملفات والتحقق من جلسة الإدارة، ولا تدخل مفاتيحها في حزمة المتصفح.
- `supabase/schema.sql`: البنية الكاملة ودوال حفظ ذرية مع فحص رقم المراجعة لمنع ضياع التعديلات المتزامنة.
- `tests/`: اختبارات المحتوى وواجهات API والتحقق من الصلاحيات وقاعدة PostgreSQL محلية عبر PGlite.
- `QA.md`: ما فُحص فعليًا وحدود الفحص.

الدخول إلى عنوان الإدارة وحده لا يعطي صلاحية. كل عملية إدارة تتحقق على الخادم من جلسة Supabase وبريد المالك وUUID الخاص به. ملفات المسودات غير عامة. يُرفض HTML التنفيذي وروابط JavaScript داخل المقالات، وتُفحص أنواع وأحجام الملفات. لا تضع مفتاح الخدمة في متغير يبدأ بـ`NEXT_PUBLIC_`، ولا ترفعه إلى GitHub.

اختبارات PostgreSQL تستخدم بيانات اصطناعية في ذاكرة مؤقتة وتُغلق بعد الاختبار؛ لا تتصل ببياناتك ولا تضيف محتوى إلى الموقع المنشور.

الواجهة لا تتضمن علامة منصة إنشاء أو شعار B أو شرط نسب الموقع إلى أي مساعد. الحزمة مستقلة ولا تحتوي على تاريخ Git أو إعدادات ارتباط بمشروع آخر. تبقى تراخيص مكتبات الطرف الثالث محفوظة.
